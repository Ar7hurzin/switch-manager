SWITCH MANAGER — COMO CONECTAR AO SWITCH E USAR
Guia para a versão com leitura por console serial

SITUAÇÃO CONFIRMADA ATÉ AQUI
O console mostrou um Quidway 3900-SI 28-Port, VRP 3.10(CN), RELEASE 0002. O status informou SSH 1.5. O conector SSH do aplicativo usa bibliotecas atuais compatíveis com SSHv2; não enfraquecemos a segurança para aceitar SSH 1.5. Por isso, o caminho preparado para o primeiro teste é o cabo console serial conectado ao computador que executa o Switch Manager.

Em 03/11/2026, o console serial foi usado pelo terminal do usuário em COM9, 9600 baud. As consultas display version e display vlan retornaram os dados mostrados nos screenshots. Isso confirma o acesso pelo terminal, mas não confirma que o coletor serial do Switch Manager tenha sido executado. O equipamento respondeu como Quidway 3900-SI 28-Port, VRP 3.10(CN), RELEASE 0002, hardware SI_REV.C. A saída permanece bruta; mapas e gráficos ainda não interpretam esses dados.

A ação **Atualizar leitura** no modo serial envia somente estas duas consultas fixas e não altera configuração. A área Configuração usa rotas separadas; o envio delas fica bloqueado por `QM_ENABLE_CONFIG_WRITES=false`. Os valores COM9/9600 também aparecem na sessão salva do MobaXterm e foram usados na leitura bem-sucedida.

Atualização de 23/11/2026: o console do S3900 e do S3000 foi alterado para 115200 baud (user-interface aux 0 → speed 115200) e salvo com save nos dois switches. A partir dessa data, use 115200 no Switch Manager e no terminal; 9600 só mostra caracteres ilegíveis.

IMPORTANTE SOBRE O CABO E ACESSO REMOTO
O computador que executa o app precisa permanecer fisicamente conectado ao switch pelo cabo console USB/serial. O Tailscale pode dar acesso privado ao painel web desse computador, mas não transporta a porta COM diretamente para outro dispositivo. Feche Tera Term/MobaXterm antes de abrir o app, porque a porta COM geralmente só pode ser usada por um programa de cada vez.

PASSO 1 — CONFIRA A PORTA E A VELOCIDADE
1. Conecte o cabo console ao computador e ao switch.
2. No Gerenciador de Dispositivos do Windows, abra “Portas (COM e LPT)” e confirme a porta. COM9 é a porta vista anteriormente; confirme que continua igual.
3. Use a mesma velocidade serial do console do switch: 115200 baud desde 23/11/2026. Atualize também a sessão salva do MobaXterm, que ainda pode estar em 9600.
4. No terminal, confirme que aparece o prompt <Quidway>. Feche o programa terminal completamente antes de seguir.

PASSO 2 — CONFIGURE O APP PARA O CONSOLE
Abra o PowerShell na pasta switch-manager. Se ainda não existir configuração local, crie-a:

    Copy-Item .\local-settings.example.ps1 .\local-settings.ps1
    notepad .\local-settings.ps1

No Bloco de Notas, habilite e ajuste estas linhas. Altere COM9 e 115200 se o Gerenciador de Dispositivos ou a sessão do terminal mostrarem outros valores:

    $env:QM_MODE = 'serial'
    $env:QM_SERIAL_PORT = 'COM9'
    $env:QM_SERIAL_BAUD = '115200'

Salve o arquivo e feche o Bloco de Notas. Deixe todas as linhas QM_MODE='real' e opções de SSH comentadas com #. Não é preciso cadastrar usuário ou senha do switch para a conexão serial, a menos que o próprio console peça autenticação.

PASSO 3 — CRIE O LOGIN DO MANAGER
Na primeira vez, execute:

    .\configure-login.ps1

O login é por SSO (OpenID Connect) com 2FA no provedor da organização; nenhuma senha de usuário é pedida ou gravada. O assistente pede o issuer, o client ID e os e-mails autorizados (veja docs/login-sso.md). O arquivo local-settings.ps1 guarda só essa configuração e uma chave aleatória da sessão; ele é ignorado pelo Git.

PASSO 4 — INICIE E CONSULTE
No PowerShell, na pasta do projeto, execute:

    .\start.ps1

Na primeira inicialização com a nova versão, o script instala as bibliotecas listadas em requirements.txt, incluindo PySerial. Mantenha a janela aberta e acesse no navegador:

    http://127.0.0.1:8787

Entre com o usuário e senha do Manager. O painel deve mostrar “MODO REAL · CONSOLE” quando estiver configurado em modo serial. O clique em “Atualizar leitura” tenta executar as duas consultas pelo próprio Manager; essa etapa ainda precisa ser verificada no equipamento. Os mapas e gráficos ainda não são preenchidos automaticamente.

PASSO 5 — SE DER ERRO
- “Não foi possível abrir COM9”: confira a porta no Gerenciador de Dispositivos e feche qualquer terminal que esteja usando-a.
- Timeout ou caracteres ilegíveis: confirme a velocidade, o cabo/adaptador, a porta COM e se o prompt do console aparece normalmente no terminal.
- Tela pedindo login: não insira senhas neste guia; use a credencial autorizada do console e, se o app não conseguir atravessar a tela de login, pare e informe a mensagem para ajustar o suporte com segurança.
- Paginação ou resposta incompleta: anote a tela/saída e pare. Não execute comandos de configuração para tentar corrigir.

Para encerrar, volte ao PowerShell do app e pressione Ctrl+C. A porta COM será liberada pelo aplicativo.

ACESSO PRIVADO DE OUTRO LOCAL (OPCIONAL)
Depois que a consulta local funcionar, mantenha esse computador ligado, com o cabo ligado ao switch e o Tailscale conectado à sua tailnet. Inicie o Switch Manager; em outro PowerShell, execute .\enable-tailnet.ps1 e siga o endereço privado HTTPS mostrado pelo Tailscale. O outro dispositivo precisa estar autenticado na mesma tailnet. Não use Tailscale Funnel e não abra portas no roteador.

ÁREA CONFIGURAÇÃO
O código local agora inclui uma área Configuração com prévias para VLANs, portas access/trunk/hybrid, descrição/estado de porta, nome do switch, IP de gestão, rotas estáticas IPv4, backup e salvar configuração. Cada plano mostra os comandos e exige frase de confirmação; qualquer alteração exige baixar e reconhecer o backup. Comandos livres não são aceitos. O painel também identifica grupos ainda não implementados/validados — como STP, agregação, SNMP, AAA/SSH, ACL/QoS, DHCP relay e NTP/syslog — então o Manager ainda não substitui a CLI para tudo.

As gravações ficam bloqueadas por padrão em QM_ENABLE_CONFIG_WRITES=false. Nenhum comando de alteração foi executado. A porta COM e as consultas de leitura funcionaram, mas comandos de escrita ainda precisam de validação específica para o release 0002. Veja docs/configuracao-interface.md antes de habilitar qualquer gravação.

ABA CLI INTEGRADA
A rota http://127.0.0.1:8787/cli abre um terminal interativo do console serial dentro do Manager. Feche Tera Term/MobaXterm, clique em Conectar ao console, digite um comando por linha e use Enviar. Não há prévia nem desfazer automático: cada linha é executada assim que enviada. O botão Enviar Enter atende prompts que pedem uma linha vazia. Não feche a aba enquanto o switch executa um comando. Encerrar sessão libera a porta COM; a sessão também fecha após 20 minutos sem atividade.

O terminal pode mostrar informações sensíveis que o próprio switch imprime, como hashes. Limpe a saída da tela quando terminar. A conexão usa o cabo console local; o Tailscale apenas permite abrir privadamente a interface hospedada neste computador. Nenhum comando foi enviado ao switch durante a implementação.
